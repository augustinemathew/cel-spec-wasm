# Repo rules for Claude — the `ts/` subtree (TypeScript eval host)

This tree is a **from-scratch TypeScript reimplementation** of the CEL→WASM
**eval half**, mirroring `compiler_v2/`:

  - `ts/eval/` — the eval host *library*: instantiates the compiled
    `Program` (`.wasm` + `cel.abi`), marshals activations, calls `$eval`,
    decodes the 24-byte result CelValue, and implements the `cel_host.*`
    proto-reflection trampolines.  Sibling of `compiler_v2/api/eval`.
  - `ts/conformance/` — the cross-host conformance *runner*: consumes the
    C++ fixture exporter's output and **zero-diffs against the C++
    host**.  Sibling of `compiler_v2/conformance`.

There is **no TS `Compiler`** — compilation stays in C++.  The TS side
receives `Program` *bytes* across the boundary and runs them.

Read `doc/implementation-plan/rewrite/m19-api-split-ts-eval-host.md` (esp.
§4 the ABI contract, §5 the host, §5.8 the testing matrix) before any
non-trivial change.  The root `CLAUDE.md` discipline (testing-is-mandatory,
probe→test graduation, close-out planning docs, no unprompted
later-milestone work) applies here verbatim — this doc adapts it to TS.

## Style authority

  - **The [Google TypeScript Style Guide](https://google.github.io/styleguide/tsguide.html)
    is canonical.**  When in doubt, do what it says.
  - **Lint** with ESLint, strict config — `typescript-eslint`
    `recommended-type-checked` (type-aware) as the floor.  Treat
    warnings as errors; do not `// eslint-disable` to dodge a rule —
    fix the code.
  - **Format** with Prettier; the formatter is authoritative (don't
    hand-format around it).
  - **`tsconfig.json` is `strict: true`** plus `noUncheckedIndexedAccess`
    and `exactOptionalPropertyTypes`.  ESM (`"type": "module"`).
  - **Before considering any work done**, in order:
      1. `npx tsc --noEmit` — must be clean.
      2. `npx eslint .` — zero warnings.
      3. `npx vitest run --coverage` — all green AND coverage at 100%
         (the config enforces 100% lines/branches/functions/statements).
      4. The `conformance_ts` zero-diff run stays green (see Testing).
      5. Tick `testing-checklist.md` + add/update the TS section of
         `per-component-test-coverage.md`.
  - One-shot: `npm run check` (typecheck + lint + format + test).

## Build & tooling — npm now, Bazel later

  - **Today: plain npm** at `ts/` (`type: module`, ESM).  `package.json`
    pins the toolchain; `npm run check` is the gate.  `node_modules/` and
    conformance `fixtures/` are gitignored — never commit them.  This is
    deliberately vanilla TypeScript: stock `tsc` / ESLint / Prettier /
    vitest, the `WebAssembly` builtin (no dep), and `@bufbuild/protobuf`
    as the *only* runtime dep.  No framework, no codegen — an eval host
    is a binary codec + wasm glue, which the platform APIs cover.
  - **Generated protobuf bindings stay in sync.** `eval/src/gen/
    cel_abi_pb.ts` is generated from `compiler_v2/abi/cel_abi.proto` by
    `protoc-gen-es` (`npm run proto:gen`) and committed. It is NOT yet
    auto-regenerated by the C++/bazel build (that lands with the
    `aspect_rules_ts` migration as a genrule). Until then a drift guard
    (`npm run proto:check`, wired into `npm run check`) regenerates into a
    temp dir and diffs — so a `cel_abi.proto` change that lands without
    `proto:gen` fails the gate. `protoc` must be on PATH for `check`. The
    `gen/**` tree is excluded from lint / format / coverage (not ours).
    **Decode the ABI with the real protobuf reader (`fromBinary` over the
    generated schema) — never hand-roll protobuf.** (Hand-rolled framing
    is allowed ONLY for the wasm section walk, which isn't protobuf.)
  - **Lint floor is the PRODUCTION set**, not `recommended`:
    `typescript-eslint` **`strict-type-checked` + `stylistic-type-checked`**
    plus hardening (`no-floating-promises`, `no-misused-promises`,
    `await-thenable`, the `no-unsafe-*` family, `switch-exhaustiveness-check`,
    `no-unnecessary-condition`, `no-non-null-assertion`,
    `consistent-type-imports`, `explicit-(module-boundary|function-return)-types`).
    Treat warnings as errors; fix the code, don't `eslint-disable`.
  - **Later: Bazel via `aspect_rules_js` + `aspect_rules_ts`** (the repo
    is bzlmod).  Migrate once the TS surface stabilises, so
    `bazel test //...` covers C++ **and** TS in one graph.  Setup:
    `bazel_dep` on `aspect_rules_js` / `aspect_rules_ts` / `rules_nodejs`
    in `MODULE.bazel`; `npm.npm_translate_lock` against the lockfile;
    per-package `ts_project` (`declaration=True` for `ts/eval`); a
    `vitest` `js_test`; ESLint as an `eslint_test`.  **The payoff:** the
    conformance gate becomes a single `js_test` with
    `data = ["//compiler_v2/conformance:conformance_ts_export",
    "//compiler_v2/runtime:cel_runtime_wasm", <corpus>]` — Bazel wires the
    C++→TS dependency natively, replacing `scripts/check_conformance_ts.sh`.
    Practices: one `ts_project` per package; **lint as a test target** so
    `bazel test` enforces it; hermetic deps via the lock (no floating
    npm, no checked-in `node_modules`); tests must not hit the network.

## Concrete Google-style rules (enforceable)

Naming:
  - `lowerCamelCase` for variables, parameters, functions, methods,
    properties.  `UpperCamelCase` for classes, interfaces, type aliases,
    enums, type parameters.  `CONSTANT_CASE` only for module-level
    consts, static fields, and enum values.
  - Treat acronyms as words: `celAbi`, `readHttpUrl` — not `celABI`,
    `readHTTPUrl`.
  - No `_` prefix/suffix on identifiers.

Declarations & modules:
  - `const` by default, `let` only when reassigned; **never `var`**.
    One variable per declaration.
  - **Named exports only — no default exports** (Google forbids them).
  - **No `namespace Foo {}`** — use ES module `import`/`export`.  No
    `import x = require(...)`.
  - Prefer `import type { … }` when a symbol is used only as a type;
    `export type` when re-exporting a type.

Types:
  - Use an `interface` (not a type alias) for an object-literal shape.
  - Array syntax sugar `T[]` / `readonly T[]`, not `Array<T>`, for
    simple element types.
  - **No `any`.**  Use `unknown` + explicit narrowing; the DataView/wire
    decode paths are exactly where `unknown`-then-narrow earns its keep.
  - Type assertions use `as`, never angle brackets; avoid assertions
    where narrowing works.
  - Mark never-reassigned fields `readonly`; prefer parameter
    properties for obvious initializers.

Functions & control flow:
  - Prefer `function` declarations for named functions; arrow functions
    for callbacks/expressions (no `function` expressions).
  - **Explicit return types on all exported functions** (Google leaves
    this to author discretion, but this repo requires it on the public
    surface — the wire/codec boundary must not infer a sloppy type).
  - Always brace control-flow bodies, even single statements.  Every
    `switch` has a `default` (and for a closed `CelKind`/`Repr` switch,
    that `default` is an invariant violation — `throw`, don't silently
    fall back; mirrors the root CLAUDE.md unreachable-default rule).
  - `===` / `!==` only.  Single-quoted string literals; template
    literals (`` ` ``) over concatenation.  Always terminate statements
    with semicolons (no ASI reliance).
  - `Number()` to parse numerics; check `NaN` explicitly.  Plain `enum`
    only (no `const enum`); compare enum values explicitly (no `!!`).

## Project correctness rules (NOT style — these prevent miscompiles)

  - **CEL `int` / `uint` are 64-bit → use `bigint`, never `number`.**
    `number` silently corrupts values past 2^53 (P-7 confirmed
    `INT64_MIN/MAX`, `UINT64_MAX`, `2^63` round-trip only via bigint).
    The `CEL_INT` / `CEL_UINT` codec arms read/write
    `DataView.getBigInt64` / `setBigUint64`.
  - **The 24-byte CelValue is little-endian — pass the LE flag
    explicitly** on every `DataView` get/set (`getUint32(off, true)`,
    `setBigInt64(off, v, true)`, …).  The C++ runtime `#error`s on a
    big-endian host; the TS codec must match byte-for-byte.
  - **No floating-point for integer wire values.**  Offsets, slot
    indices, ptr/len spans are `number` *only* where they are genuinely
    ≤32-bit memory offsets; i64/u64 *payloads* are `bigint`.  Never
    route an i64 through `number` "for convenience".
  - **Bytes are `Uint8Array`**, not strings.  STRING/BYTES payloads are
    a `{ptr, len}` span into shared linear memory; decode strings via
    `TextDecoder('utf-8')`, keep BYTES raw.
  - `repr` in `cel.abi` is the `ir::Repr` ordinal, **not** `CelKind` —
    the repr→encoder dispatch table keys on Repr ordinals (§4.2).

## Testing — mandatory (same discipline as the C++ tree)

  - **vitest.**  Every module ships **positive + negative + boundary**
    tests **in the same commit** as the code.  "Add tests later" is
    shipping a regression surface.
  - **100% coverage is enforced** (`@vitest/coverage-v8`,
    `vitest.config.ts` thresholds = 100% lines/branches/functions/
    statements, `all: true` so an untested module reads 0% rather than
    going uncounted).  This is a binary codec + wire host — a missed
    branch is a latent miscompile, so the bar is 100%, not "high".
    Lower a *specific* threshold only with a written justification for a
    genuinely unreachable defensive arm; never blanket-lower.  Coverage
    is necessary but NOT sufficient: it proves lines ran, not that the
    asserted values are spec-correct — the edge-matrix below + the
    conformance gate carry that.
  - **Enumerate the edge matrix explicitly** — a codec/host port
    miscompiles silently on the input shape nobody tested.  At minimum:
    `INT64_MIN`, `INT64_MAX`, `UINT64_MAX`, `0`, `-1`, `2^63`; empty
    string, embedded NUL, multi-byte UTF-8; `NaN`, `+Inf`, `-Inf`;
    sign-correlated duration/timestamp; unknown `CelKind` byte; span
    ptr/len past memory; cross-type numeric equality (int/uint/double);
    3VL absorb of unknown/error operands.  Negative coverage is the
    load-bearing half.
  - **`conformance_ts` zero-diff is the spec gate** — the analog of the
    C++ conformance baseline.  For every exported (compiled) row,
    `ts_outcome` MUST equal `cpp_outcome`; any row that passes where C++
    failed (or vice-versa) is a diff and fails the gate.  Every TS
    change keeps it green.  The corpus diff does NOT absolve the
    per-component unit tests.
  - **Probes are NOT tests.**  Probes under `ts/eval/probes/` are
    throwaway and are deleted at milestone close.  Every behavior a
    probe validated MUST graduate into a permanent vitest test before
    closeout (the §5.8 graduation table is the checklist) — e.g. P-7's
    bigint extremes → `celvalue.test.ts`, P-5's string-buffer marshal →
    `instance.test.ts`, P-6's byte-parity → `host/*.test.ts`.
  - Write cases out longhand first; consolidate structurally-identical
    ones into a parameterized table once the matrix is settled; keep
    distinct-story cases (a specific bug, a spec citation) as their own
    test.  Cite the langdef.md section when asserting spec-mandated
    behavior.

## Public API documentation — code samples are mandatory

  - **Every public symbol a customer imports MUST carry a runnable code
    sample in its doc comment.**  This is the surface in `eval/src/index.ts`
    — `Engine`, `Program`, `Instance`, `Activation`, `Value` (every
    factory + every `asX`/`isX` accessor), `TypeRegistry`, the backings,
    the error classes.  If a customer can `import { Foo } from
    '@celwasm/eval'`, then `Foo`'s TSDoc has an `@example` showing how to
    use it.  An exported symbol with no sample is an incomplete API and
    fails review.
  - Use a **TSDoc `@example` block** with real, compilable code (the same
    shapes as `eval/README.md` and the e2e):

    ```ts
    /**
     * Per-Eval variable bindings (mirrors `cel::Activation`).
     *
     * @example
     * ```ts
     * const act = new Activation()
     *   .bind('a', Value.int(6n))
     *   .bind('s', Value.string('hi'));
     * const result = instance.eval(act);
     * ```
     */
    ```

  - Keep samples **honest and current**: they show the *actual* signatures
    (e.g. `Value.message(registry.message(msg))`, not a signature that was
    refactored away).  When an API changes, its sample changes in the same
    commit — a stale sample is worse than none.  The canonical end-to-end
    flow lives in `eval/README.md`; per-symbol `@example`s are the
    close-up of each piece.
  - Internal (non-exported) helpers don't need samples — describe what
    they do and why, per the usual comment discipline.  The bar is: *is it
    in the public surface a customer touches?*  If yes, sample it.

## Layout

  - `ts/eval/` is a **library**; `ts/conformance/` is the **runner**.
    Keep them separate packages with their own toolchain.
  - **Mirror the C++ component names** so a reader can pair them:
    `celvalue.ts` ↔ `instance.cc DecodeCelValueAt`, `abi.ts` ↔
    `abi_decode.cc`, `engine.ts` ↔ `engine.cc Plan`, `instance.ts` ↔
    `instance.cc Eval/MarshalActivation`, `externref.ts` ↔
    `HostExternrefTable`, `host/*.ts` ↔ `cel_host.cc` Layers 1+2.
  - **One concern per module.**  Codec, ABI decode, WASI shim,
    externref table, each trampoline group — separate files.  Public
    surface (`Engine` / `Program` loader / `Instance` / `Activation` /
    `Value` / `CelType`) mirrors `doc/user-guide.md`.
  - **Runtime deps minimal:** `@bufbuild/protobuf` (descriptor pool /
    reflection) is the only library dep; `WebAssembly` is a JS builtin
    (no dep, no polyfill); the WASI shim is hand-rolled.  Don't add a
    dep without justifying it against this floor.

## What not to do

  - Don't use `any` — `unknown` + narrowing.
  - Don't use `number` for a CEL `int`/`uint` — `bigint`, always.
  - Don't omit the little-endian flag on a `DataView` access.
  - Don't use default exports; don't use `namespace`.
  - Don't ship a feature without its positive/negative/boundary tests
    in the same commit.
  - Don't let the `conformance_ts` zero-diff run regress.
  - Don't treat a probe as a test — probes are deleted; graduate their
    coverage into vitest first.
  - Don't reimplement the CEL compiler/parser/checker in TS — the TS
    side consumes `Program` bytes only.
  - Don't create work for later milestones (custom fns, Go host,
    PartialEval) unprompted — stay in the requested slice.
