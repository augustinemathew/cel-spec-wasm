# M3 — cel_arena rewrite: bump arena over `malloc`

Status: **shipped 2026-05-18.**

## Acceptance

`bazel test //compiler_v2/runtime/...` passes (14 / 14 tests
green).  The new arena module exposes `arena_init` /
`arena_alloc` / `arena_reset` / `arena_cursor` / `arena_capacity`,
plus compat shims `cel_reset` / `cel_alloc` that keep the 107
pre-migration call sites in the 6 kernel `.c` files working
unchanged.

## What landed

1.  **`compiler_v2/runtime/cel_arena.h`** (rewritten, ~75 LoC):
    New ABI surface — `arena_init(cap_bytes)`,
    `arena_alloc(n)`, `arena_reset()`, `arena_cursor()`,
    `arena_capacity()`.  Old `cel_alloc(n)` / `cel_reset(b, l)`
    kept as compat shims (route to `arena_alloc` /
    `arena_reset`; ignore base/limit args).  `cel_value_at`
    unchanged.

2.  **`compiler_v2/runtime/cel_arena.c`** (rewritten, ~110 LoC):
    Bump arena over a malloc'd backing buffer.  Native vs wasm
    split via `#ifdef __wasm__`:
    - **wasm**: backing buffer comes from dlmalloc via wasi-libc.
      `arena_alloc` returns `(uint32_t)(uintptr_t)(base + cursor)`
      — an offset into linear memory, so
      `cel_mem_base() + ret` (cel_mem_base = 0 on wasm) resolves.
    - **native**: backing buffer is the static `g_memory[16..]`
      slice (so `cel_mem_base() + offset` reads the right
      bytes during host tests).  `arena_alloc` returns
      `16 + cursor`.

    Compat shim auto-inits the arena on first `cel_reset` call
    so existing tests / codegen don't need to add explicit
    `arena_init` calls during the migration window.

    Implements asserts A9 (`alloc(0)` returns 8-byte slot), A10
    (`arena_alloc` returns 0 on OOM, never a partial offset),
    A16 (re-init with different cap traps; same-size is a no-op).

3.  **`compiler_v2/runtime/cel_arena_test.cc`** (rewritten):
    New tests against the malloc-backed API.  Cover: 24-byte
    CelValue invariant, reset rewinds cursor, alloc bumps
    monotonically, 8-byte alignment, alloc returns zeroed
    bytes, exhaustion → 0, cursor reflects allocations,
    `cel_value_at(0)` returns null, compat shim parity with
    `arena_alloc`.

## Plan-vs-execution deltas

  - **Native vs wasm path divergence.**  The original M3 sketch
    assumed `arena_alloc` could return a raw pointer cast to
    uint32 in both builds.  On 64-bit native, that truncates
    the host pointer (64-bit) to a meaningless 32-bit value;
    the kernels then do `cel_mem_base() + truncated` and
    segfault.  Split with `#ifdef __wasm__`: wasm returns the
    absolute linear-memory offset; native returns
    `16 + local_cursor` relative to `g_memory[0]`.

  - **Native backing buffer collision with `g_memory[]`.**
    Plan said arena would be a separate `malloc()`.  But the
    native build's tests address bytes via `cel_mem_base() +
    offset`, expecting a single contiguous backing.  Routed
    the native arena's base to `cel_mem_base() + 16` so the
    contract holds without a separate buffer.

  - **`cel_arena_test.cc` rewritten entirely.**  The old tests
    asserted bytes-8/12 cursor semantics that no longer exist.
    9 new test cases now cover the malloc-backed arena's
    behaviour.

  - **Auto-init in `cel_reset` shim.**  Without it, every test
    fixture would need an explicit `arena_init` call.  The
    shim auto-inits on first call with
    `CELWASM_ARENA_CAPACITY_BYTES`; subsequent calls just
    rewind.  Deletes when Phase B rewrites the call sites to
    drive `arena_init` from the host.
