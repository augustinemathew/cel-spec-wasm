# 2026-07-25 — m35 closeout review (plugin ergonomics)

Scope: `git diff 9015f11..e347557` (the full m35 range: rename R,
abi layer A, embed-decls A2/A3, Use surface B, Plan verification V,
doc site S).  Plan of record: `rewrite/m35-plugin-ergonomics.md` +
`rewrite/m35-dag.md`.  Focus per the review brief: duplication that
survived the ~3,039 added production lines, deletable/mergeable
code, the celfn_wire/cel_abi_emit/required_fn_check seam, engine.cc
factoring, and whether the `//abi:wasm_binary` consolidation
actually consolidated.  Review only — no code was changed.

## Verdict

**Mixed, leaning clean.**  The m35 production surface is unusually
well-factored for its size: the as-built shape matches the plan doc
section-for-section (every delta is recorded as a dated callout),
the `//abi:wasm_binary` consolidation is 100% clean in production
code (a repo-wide grep finds zero residual magic constants or LEB
decoders outside `abi/wasm_binary.cc`), every new TU ships a paired
test with frozen-message pins, and the celfn_wire seam is the right
shape (one converter, one comparer, one renderer — no redundant
traversal).  No P0 findings.  The top 3 items: (1) **the milestone
is not closeable on this review alone** — slice N (benchmarks,
incl. the §6.4 selective-instantiation before/after headline) and
B4/G (testing-checklist rows, plan-doc status flip, probe deletion,
gates) are still pending per the DAG; (2) **a three-way duplication
of the celfn rendering vocabulary** shipped — `RenderCelfnType`
(compiler.cc) vs `RenderFnType` (celfn_wire.cc) have already
diverged (`duration` vs the grammar's `Duration`; `map<k,v>` vs
`map<k, v>`), and `BackendPrefix` is copy-pasted verbatim into two
files with a third near-copy in engine.cc; (3) **engine_test.cc
carries a surviving hand-rolled LEB128 codec + section walker**
(lines 1220–1269) despite including `abi/wasm_binary.h` — a direct
violation of the "any LEB decoder anywhere else is a review
finding" rule that m35 itself legislated in `wasm_binary.h`.

## 1. Architectural drift vs the plan

Overall: minimal, and honestly recorded.

- **§5.2 post-optimize attach — as designed.**  `FinaliseModule`
  split into `ValidateAndOptimize` + `SerializeModule` with the
  `cel.abi` attach between them (`compiler/internal/compile.cc:643`),
  exactly the §5.2 restructure; the required-functions table derives
  from `WasmModule::ListFunctionImports()` post-optimize.
- **§6.4 selective instantiation — as designed, incl. the
  empty-table compat delta** (`eval/engine.cc:1260`), matching the
  plan's as-built callout (empty table = legacy instantiate-all,
  proto3 no-presence).
- **abi → compiler/celfn edge** (`//abi:plugin` and `//abi:celfn_wire`
  dep on `//compiler/celfn:function_library`) — sanctioned by plan
  §3.1 and documented in `abi/plugin.h`/`abi/BUILD.bazel`, but the
  repo-level layering prose (CLAUDE.md's role-dir summary,
  `rewrite/design.md`) doesn't yet state abi's allowed dep set.
  One sentence at closeout keeps the next reader from flagging it
  as a violation.  (Correction target: the docs, not the code.)
- **Wire enum `FN_KIND_TYPE` / `FN_KIND_OPTIONAL` are currently
  unreachable from emission**: `Compiler::Builder::Build()` now
  rejects `type`/`optional<T>` on every library
  (`ValidateDeclTypesMappable`), and the kPlugin surface already
  rejected them at `FunctionLibrary::Builder::Build`.  Consistent
  with the §5.1 "1:1 mirror, open set" intent — not drift, but
  worth knowing they're mirror-completeness, not live paths.
- **`Engine::Use` vs `AddPlugin` status asymmetry** (parse failure →
  InvalidArgument vs FailedPrecondition) matches the §3.4 per-phase
  table verbatim; engine.h documents both.  Not drift.
- Plan §2's quoted overload-id spelling (`is_adult_proto_acme_user`)
  differs from the landed synthesizer
  (`is_adult_message_acme_User`) — already corrected by the plan's
  own dated as-built callout; the pinned strings in
  `required_fn_check_test.cc` are the contract of record.  Good
  discipline; nothing to do.

Not worth doing / explicitly cleared:

- **The celfn_wire seam (brief item c) is sane.**  One direction
  each: `FnTypeFromCelfn` (celfn→wire), `FnTypeEquals` (wire↔wire),
  `RenderSignature`/`RenderFnType` (wire→string).
  `required_fn_check` compares by converting the registered decl to
  wire (`RequiredFunctionFromDecl`) and reusing the single comparer
  — the alternative (a second celfn↔wire comparer) would be the
  duplication.  No redundant traversal found.  Micro-nit: the
  conversion re-runs per Plan per row; caching wire rows on
  `RegisteredPlugin` at registration would drop it, but it's
  O(rows) proto building per Plan — not worth it until a bench says
  otherwise.
- **engine.cc factoring (brief item d) is tight.**  `Plan()` is a
  ~40-line phase list; the V3 check lives in its own TU
  (`required_fn_check`) as planned; `Use`/`AddPlugin` share
  `CheckPluginOverloadCollisions`; the static export check is one
  helper mirroring the Plan-time lookup.  Residual: D4 above, and
  at 1,794 lines engine.cc is the largest eval TU — the plugin
  dispatch block (trampolines + instantiation, ~lines 829–1306) is
  a natural `eval/internal/plugin_dispatch.cc` extraction *next
  time it's touched*, not standalone churn.
- **Dead-ish API:** `IsComponentBinary` (`abi/wasm_binary.cc:71`)
  has zero production callers (both consumers use
  `ClassifyWasmBinary` directly to distinguish error messages).
  3 lines; keep-for-symmetry with `IsCoreModule` is defensible —
  delete or leave, either is fine.
- **String-constant scatter (P2-trivial):** `kCelFnsSection`
  ("cel.fns") declared in both plugin.cc and run_embed_decls.cc;
  the `cel_fn` module name lives as `kCelFnModule`
  (cel_abi_emit.cc), inline `"cel_fn"` in function_library.cc, and
  `"cel_fn", 6` literals in engine.cc.  Hoist opportunistically
  (rides naturally on D2/D3's shared-helper home).
- **Pre-existing, grandfathered:** `OverloadIdToKebab` (engine.cc)
  vs `SnakeToKebab` (wit_emitter.h) — semantics differ slightly
  (engine also lowercases), and eval must not dep the compiler
  emit pipeline; a shared home would be function_library.  m24
  vintage, not m35's — opportunistic only.

Realistic consolidation total: **~145–185 LOC** across D1–D6, none
of it risky (all diagnostics/validation paths with pinned messages
— the pins make the refactors safe to verify).
