## Fixable vs out-of-scope (read this first)

The 744 skips split into **357 schedulable** and **387 permanent**. The
permanent ones will NEVER flip to PASS — they are out of scope by
design, and counting them as "backlog" overstates the reachable ceiling.

| Bucket | Categories | Rows | Schedulable? |
| --- | --- | ---: | --- |
| **Fixable** | eval_unimpl, bindings, envelope, proto_unimpl, ext_unimpl, cli_limitation, type_env | **357** | **yes** — closing the blocker flips skips to passes |
| **Out-of-scope by design** | static_subset, disable_check, check_only | **387** | **no** — permanent skips, not a backlog |

Out-of-scope detail (do **not** schedule these):

- **`static_subset` — 218 rows.** `dyn` / dynamic-typing constructs the
  compiler's `RejectDyn` gate drops by design. The binding accepts only
  the static subset (`bindings/ts/CLAUDE.md` "Scope"); these can never
  pass. Concentrated in `dynamic` (the whole file is `dyn`), `optionals`,
  `comparisons`, `proto2/3`.
- **`disable_check` — 144 rows.** Parse-only eval rows (`disable_check:
  true`) outside the conformance compile+check scope. Permanent.
- **`check_only` — 25 rows.** `typed_result` no-eval check-path rows (all
  in `type_deduction`). The harness compiles + evals; a check-only row
  has nothing to eval. Permanent.

Everything below the out-of-scope block is the real backlog.

### Backlog reading

The schedulable work concentrates in three themes:

1. **Proto / WKT construction + presence (eval_unimpl, proto_unimpl).**
   The single biggest unlock is **WKT-typed field construction from a
   scalar (110 rows)** — teaching `@cel-wasm/eval`'s `cel_set_field` to
   wrap a scalar into the target WKT message. With proto field-presence
   (10), null-pruning (8), out-of-range enum assignment (4), unset-nested
   reads (4+2), and FloatValue narrowing (1), the proto-construction
   theme alone is ~139 fixable rows.
2. **Object bindings (bindings, 77 rows).** A single blocker — "cannot
   bind an object value" — across 7 files. Marshalling structured
   (object) activation values would flip all 77 at once.
3. **Matcher-surface envelope (envelope, 59 rows).** `type_value` (36) +
   `typed_result` (22) + one stray. These need a comparator for
   CEL_TYPE results and a check-path matcher — note the `typed_result`
   22 overlaps the `type_deduction` check-only domain, so part of this
   is arguably out-of-scope-adjacent; the `type_value` 36 (conversions /
   enums / timestamps) is the cleaner unlock.

`google.protobuf.Any` (14 + 8 = 22 rows) is tagged `proto_unimpl` but is
**out of scope by design** per §A.3 ("Any beyond the supplied
descriptors") — it appears in the fixable table because the category is
nominally fixable, but the specific Any blocker is not schedulable.
Treat the Any rows as quasi-permanent.

## How to regenerate

```sh
cd bindings/ts
npm run build
# Full corpus (slow — each row shells out to the cel CLI; ~minutes):
vite-node conformance/src/run.ts -- --breakdown
# or a subset:
vite-node conformance/src/run.ts -- --files proto2,proto3 --breakdown
```

The `--breakdown` flag prints the per-file table + the ranked
skip-reason groups (each tagged FIXABLE / BY-DESIGN) after the summary.
The aggregation lives in `conformance/src/breakdown.ts` (unit-tested in
`breakdown.test.ts`); it adds **no** classification logic — it only
re-aggregates the outcomes `runner.ts` / `classify.ts` already produce.
