# `doc/` — documentation index

The map of the cel-wasm documentation tree, routed by what you're here
to do.

> **Live numbers live in code, not here.**  The authoritative
> conformance headline (pass/skip/fail) is the autogenerated block in
> [`../conformance/README.md`](../conformance/README.md).  Pass-counts
> and perf figures quoted in milestone docs are point-in-time snapshots
> from when that milestone shipped — historical, not current.  Current
> benchmark numbers come from re-running
> [`../benchmark/eval/run.sh`](../benchmark/README.md).

## Understanding the design

**[`design/`](design/) is the canonical architecture doc set** (the
2026-06 design rebuild).  It supersedes the architecture content that
was scattered across `implementation-plan/rewrite/` (those docs remain
as milestone history — see below).  Read it in order; each part is
verified against the code it describes.

| Part | What it covers |
| --- | --- |
| [`design/00-architecture.md`](design/00-architecture.md) | **Start here.** The problem, the four-role lifecycle, the static/dynamic link-mode fork, the data contracts the roles exchange, the threading model. |
| [`design/01-compiler.md`](design/01-compiler.md) | The compiler pass pipeline: parse/check → IR → resolve → layout → codegen → assemble. |
| [`design/02-evaluator.md`](design/02-evaluator.md) | The evaluator: Plan (instantiate + JIT), Eval, activation marshaling, result decode. |
| [`design/03-abi-and-memory.md`](design/03-abi-and-memory.md) | The wire contracts: `cel.abi` schema, slot layout, the linear-memory map, the reserved-window discipline. |
| [`design/04-runtime.md`](design/04-runtime.md) | The `runtime/` kernel: the chained arena, slot accessors, host trampolines, the stripped-runtime static-link variant. |
| [`design/05-custom-functions.md`](design/05-custom-functions.md) | The `.celfn` custom-function subsystem: `@host` / `@plugin` backends, the IDL, dispatch. |
| [`design/06-testing-strategy.md`](design/06-testing-strategy.md) | The testing system: the per-component matrix, conformance, the oracle, property-based testing, the closeout gate. |
| [`design/07-benchmarking.md`](design/07-benchmarking.md) | The benchmark methodology: the corpus, the three-way harness, the honest win/loss framing. |
| [`design/diagrams/`](design/diagrams/) | Rendered SVGs (pipeline, dependency graph, memory map, trust boundary) + `render.py`. |
| [`design/notes/`](design/notes/) | The verified per-component + cross-cutting notes the design set is authored from — raw material with citations, not narrative. |
